# MVGAL Documentation

Documentation for **MVGAL**, an experimental Linux project for multi-vendor GPU discovery, capability reporting, workload coordination and API-specific integrations.

> These pages describe source version **0.7.43**. The project is not a universal transparent multi-GPU driver. Device ownership stays with native vendor drivers, and actual operation support depends on build options and runtime capability probes.

The source repository is organized around a Linux kernel module (`kernel/`), public interfaces (`include/mvgal/`), userspace APIs and integrations (`src/userspace/`), the C++ daemon (`runtime/daemon/`), Rust components (`safe/` and `runtime/safe/`), tools, bindings, compatibility helpers and package recipes. See the [Codebase Map](docs/CODEBASE.md) for details.

## Current implementation limits

- MVGAL does not bind GPU PCI functions; native vendor drivers continue to own submission and memory management.
- API symbols, strategy names, vendor adapters and ioctl declarations do not establish that an operation works on a given device.
- Unsupported operations must be treated as unsupported; use runtime capability reporting and the documented fallback for each path.
- The Vulkan interception layer and optional ICD are separate. The ICD does not publish a fabricated aggregate physical device.
- Synthetic GPU topologies are a userspace test fixture; they do not create hardware or establish physical multi-vendor validation.
- The source changelog's 0.7.24 known-issues note records that the PCI enumeration use-after-free fix is source-verified only and still needs a clean-boot check on the host where it was found; the 2026-10-25 bench run does not substitute for that check on the affected machine.

## Recent source changes (through v0.7.43)

- **Execution and diagnostics (v0.7.43)** — adds a daemon execution-backend contract with OpenCL and mock implementations, wires the scheduler through IPC and D-Bus, and adds `mvgal-exec` and `mvgal-doctor`. The mock exercises software paths and is not physical GPU validation.
- **Teardown and diagnostics (v0.7.42)** — prevents thermal/DVFS work from rearming during stop, detects wedged modules across unload inventory, removes forced-removal fallback, bounds polkit wait, and improves daemon-down status output.
- **DKMS module placement (v0.7.41)** — aligns `mvgal_ntsync` rebuild destination with RPM packaging.

- **The Vulkan ICD builds on Vulkan 1.2 systems (v0.7.39)** — the ICD's compile check only ran when a Vulkan include directory had been discovered, so pkg-config reporting a 1.2 SDK was taken as "headers are 1.3 or newer" and openEuler 22.03 failed with `unknown type name 'VkPhysicalDeviceToolProperties'`. The check now always runs and the ICD target is skipped with a warning when 1.3 headers are absent, so the rest of MVGAL still builds and installs there. The ICD library and manifest are listed from a generated file list, so `%files` no longer depends on hand-maintained globs. COPR build #11261576: all 60 chroots green.

- **openEuler 22.03 could not compile the Vulkan layer (v0.7.38)** — its headers are Vulkan 1.2, where `VkDependencyInfo` and `PFN_vkCmdPipelineBarrier2` do not exist. `include/mvgal/mvgal_cmd_dag.h` now derives `MVGAL_HAVE_SYNC2` from `VK_VERSION_1_3`/`VK_KHR_synchronization2`, keeps a barrier payload as an opaque handle, and gates the lowering helpers and the `vkCmdPipelineBarrier2` slot; a recorded sync2 barrier on such a build reports `VK_ERROR_FEATURE_NOT_PRESENT` with an explanatory log instead of being dropped. Vulkan 1.3 builds are unchanged, runtime lowering included.

- **The 0.7.32 test report (v0.7.33 – v0.7.37)** — every tool now shares `tools/mvgal_device_state.h`, which really opens `/dev/mvgal0` and reports not-loaded / wedged / loaded-but-unusable / OK instead of trusting `stat()`, so `mvgal-hw-validate`, `mvgal-probe`, `mvgal-info`, `mvgal-status` and the daemon agree about the same node. The kernel-module wedge (module stuck in `Unloading` with refcount −1 and `/dev/mvgal0` returning ENXIO until reboot) was an idle-gate sweep that re-queued itself unconditionally, so `cancel_delayed_work_sync()` never returned during teardown; the sweep now honours a stopping flag, and `unload-module` detects that state up front and says a reboot is required instead of "still in use". Strategy changes reach a running daemon (`mvgal set-strategy` and `mvgal-config` reload it after saving and say whether the change is live), `--force` is documented in `--help` and the man page and emits the same single-GPU fallback warning as `mvgal-config -f`, `mvgal set-strategy --help` exists, `show-stats` prints a `Daemon: NOT RUNNING` banner and exits 2, `mvgal-status --once` returns the documented exit 2, `mvgal restart` on a stopped daemon says it started it, `set-strategy custom` warns when the script is missing and notes the shipped stub is a no-op, the Vulkan ICD is one line (`available, not registered (opt-in)`), benchmark help no longer claims a daemon is required, bash/zsh/fish completions ship, internal engineering docs are excluded from the RPM, dashes are ASCII, `Also see:` lists the companion tools, and JSON output is clean. The release also added shader intermediate-format detection and routing for SPIR-V, PTX, cubin, fatbin, hsaco, LLVM IR/bitcode, assembly and Intel GEN.

- **Distribution portability (v0.7.33 – v0.7.37)** — `runtime/daemon/kernel_ioctl_types.hpp` no longer hard-requires `drm/drm.h` (`__has_include()` plus equivalent `_IOC` definitions, unblocking openSUSE Leap 16 and Mageia Cauldron aarch64); `mvgal_ccl_transport.c` uses a per-arch pause instead of the x86-only `__builtin_ia32_pause()`; `kernel/mvgal_modinfo_compat.h` emits `MODULE_IMPORT_NS()` so the `.modinfo` dma-buf record is identical across kernel releases; the spec defines `cmake_build`/`cmake_install` fallbacks for chroots with no `cmake-rpm-macros`, builds whichever directory actually received the CMake cache, keeps section macros out of comments, drops the build-time `dkms` BuildRequires, and guards `Recommends` for RPM older than 4.12; and `vk_layer.c` provides a local `VK_API_VERSION_1_3` for Vulkan 1.2 headers.

- **GPU index mismatch / udev permissions / blacklisted GPU visibility / start degraded (v0.7.31)** — `mvgal_enumerate_gpus()` now includes `PCI_CLASS_DISPLAY_OTHER` (0x0380) so Intel integrated GPUs are found alongside discrete cards, and skips display-class PCI devices whose native driver is not bound (blacklisted MTT S30), so kernel and userspace enumeration agree on GPU indices; `mvgal_mtt.c` checks `MVGAL_FULL_STACK` instead of the non-existent `CONFIG_MVGal_MTT` typo and uses `/proc/modules` instead of the `find_module()` symbol removed in kernel 7.x; udev rules and the pkexec helper set `GROUP="mvgal"` and `MODE="0660"` (were `GROUP="video"` and `MODE="0666"`); `mvgal-enum` and `mvgal list-gpus` scan PCI for display-class GPUs with no DRM node and warn about present-but-unusable devices; `mvgal start` checks for `/sys/module/mvgal` after launching the daemon and prints a degraded-mode warning if the kernel module is absent. COPR build #11229933 succeeded on `fedora-43-x86_64`.

- **Vulkan ICD opt-in / OpenCL stepping-aside / GUI refresh / bench caveats / exit codes / log spam / man pages / preset** (v0.7.30) — `mvgal-vulkan-env.sh` no longer forces `VK_ICD_FILENAMES`/`VK_DRIVER_FILES` to *only* the MVGAL ICD (which reports zero devices when the kernel module is absent); default `MVGAL_ICD_ONLY=0` preserves vendor ICDs as fallback, the duplicate `MVGAL_VULKAN_ENABLE` export and stale `VK_LAYER_PATH` are normalized, and `MVGAL_PREFIX` defaults to `/usr`; the OpenCL ICD reports zero platforms when the kernel module is absent instead of exposing a half-working platform whose context creation fails; the GUI dashboard status cards auto-refresh on startup via a single-shot `QTimer` instead of staying "Checking…"; `mvgal-bench compute` and other single-suite paths now print the "What is actually measured" caveat block like `all`; usage/error paths are standardized to exit `2` across tools (documented in the man pages); the two configuration log lines are `DEBUG`-only and gated behind `--verbose`; `%post` removes leftover `/etc/OpenCL/vendors/mvgal.icd.disabled`; man pages added for `mvgal-gui`, `mvgal-dashboard`, `mvgal-load`, `mvgal-unload`, `mvgal-workload`, `mvgal-probe`; `mvgal-daemon.preset` (disabled) documents that `%post` enables the unit on first install. COPR build #11217288 succeeded on all 18 chroots.

- **Vulkan layer env var and config/security/status/bench fixes** (v0.7.29) — `VK_LAYER_MVGAL=1`/`ENABLE_MVGAL=1` corrected to `MVGAL_VULKAN_ENABLE=1` in `--help`, `mvgal-config`, `mvgal-steam-setup`, `mvgal-vulkan-env.sh` and Steam compat scripts; `/etc/mvgal` hardened to `0755 root:root` with `custom_strategy.lua` at `0644 root:root` (was `0775 group:mvgal`, a local privilege-escalation path); `mvgal status`/`mvgal-status` now use three-tier exit codes (`0` healthy, `1` degraded, `2` daemon down); benchmark subcommands forward `mvgal-bench` output instead of suppressing it; `set-strategy` refuses multi-GPU strategies on single-GPU machines; `mvgal-config show-config` handles `ENUM` types and defaults to effective view; `-c/--config` rejects paths outside `/etc/mvgal/`; start/stop are idempotent; OpenCL ICD park moved to `/usr/lib/mvgal/`; `mvgal-workload` skips the MVGAL aggregating ICD platform; `mvgal-probe` demotes `/dev/mvgal0` open failure to a notice; `listen_addr` defaults to `127.0.0.1`. COPR build #11212845 succeeded.

- **CUDA multi-device attribution was wrong, and device counts were fabricated** (v0.7.28) — the shim returned the MVGAL GPU count from `cuDeviceGetCount`/`cudaGetDeviceCount` instead of the native driver's, and mapped CUDA ordinals to MVGAL GPUs by modulo, so CUDA device 0 (RTX 3050) was attributed to MVGAL GPU 0 (Intel Arc). v0.7.28 probes each ordinal's PCI BDF once and matches it against the NVIDIA MVGAL GPUs, passes native counts through, rejects the `-1` sentinel before `cuCtxCreate`/`cuMemAlloc`/`cuLaunchKernel` (the old `mvgal_gpu < gpu_count` guard was true for `-1`), restricts kernel launches to eligible GPUs, and lets `MVGAL_CUDA_DEBUG=1` raise the log level so the attribution line is visible. A new `test_cuda_multidevice` LD_PRELOAD harness asserts ordinal resolution, BDF set equality and `cuCtxCreate` attribution; ctest is 27/27 (4.73 s) on the bench. The release also adds a Windows cross-compilation packaging pipeline (NSIS and WiX installers from `Jenkinsfile.windows`), and the RPM ships a `systemd-sysusers` fragment so the `mvgal` group is declared before dependency resolution — `dnf install` no longer fails with `nothing provides group(mvgal)`.

- **Valid AMD hardware looked missing, and NVIDIA reported no stats** (v0.7.27) — the Vulkan ICD filename check only matched `amd`/`radv`/`intel`/`mtt`, but Fedora ships mesa's manifest as `radeon_icd.x86_64.json`, so AMD GPUs were reported as having no Vulkan driver; the AMD shader-backend list probed mesa's software rasterizer (`libvulkan_lvp.so`) instead of the real RADV paths; the WoW64 check only looked in `/usr/lib`, so multilib Fedora reported the layer "not built" despite a correct install; and `mvgal-info` left NVIDIA temperature and utilization at their `-1` sentinel because the proprietary driver exposes no hwmon `temp1_input`/`gpu_busy_percent`. The tool now fills only those empty fields from NVML by PCI bus id, leaving the sentinel when NVML is unavailable.

- **A built `mvgal-workload` could not be packaged** (v0.7.26) — CMake builds the tool whenever it finds OpenCL, but the RPM files list made its inclusion conditional, so a Fedora build that found OpenCL failed in `%install` with `Installed (but unpackaged) file(s) found: /usr/bin/mvgal-workload`. The files list now always includes what the build produces. The same release fixed the AppImage dependency self-check (the `ldd` walk now resolves `not found` entries and the final check runs against the staged `usr/lib`) and normalized the application icons to 256×256, which the Flatpak, RPM and AppImage exports require.

- **The modules could not be decompressed, so enrolling the MOK could not make them load** (v0.7.25) — they were compressed with `xz -9e`, producing a CRC64 xz stream, and the kernel's xz decoder rejects any check type above CRC32 (`lib/xz/xz_dec_stream.c`; it only carries an internal CRC32). The module failed at decompression with `Invalid parameters`, *before* the Secure Boot signature was checked, so the documented recovery — enroll, reboot, confirm — still left the system broken. CRC64 is xz's default check at every level, so `xz -9` was equally broken. v0.7.25 uses the kernel's own settings (`xz --check=crc32 --lzma2=dict=1MiB`), byte-identical to what DKMS builds. The signer also repairs modules that were already signed correctly but compressed wrongly, and `mvgal-enroll-mok` now re-signs before queueing the certificate.
- **`systemctl reload mvgald` failed permanently** (v0.7.25) — the daemon chowned systemd's `RuntimeDirectory=/run/mvgal` to `root:mvgal`, and systemd requires `root:root`, so every reload after the first start failed with `status=233/RUNTIME_DIRECTORY` while `restart` kept working. Separately, SIGHUP was installed but the handler had no case for it, so a reload did nothing and still reported success. Both are fixed: the daemon leaves the directory alone and now re-reads the configuration on SIGHUP.
- **The D-Bus API refused every non-root call** (v0.7.25) — the methods were registered without `SD_BUS_VTABLE_UNPRIVILEGED`, so sd-bus applied its own default policy and rejected them with `AccessDenied` regardless of the bus policy that allows the `mvgal` group. The GUI and dashboard were dead for members of that group.
- **"Vulkan aggregated ICD: ACTIVE" was a false positive** (v0.7.25) — the staging copy in the opt-in directory was treated as a registration. The ICD now reports registered / available / absent, and never says ACTIVE for the staging copy.
- **The OpenCL ICD registration was frozen at install time** (v0.7.25) — the decision was made from a snapshot of the machine, so on a host where the vendor runtime was installed after MVGAL the manifest stayed parked and every OpenCL application ran without MVGAL in the path. The decision moved to `/usr/lib/mvgal/mvgal-opencl-icd.sh`, which can be re-run, and the manifest is registered by default.
- **The tools stopped describing a system that was not in the state they claimed** (v0.7.25) — module load failures are classified instead of always being blamed on Secure Boot; a multi-GPU strategy is refused on a one-GPU machine; shared system RAM is no longer presented as dedicated VRAM; `mvgal-compat` and `mvgal-dashboard --check` have meaningful exit codes; `mvgal-steam-setup --check` reports the real runtime state; `mvgal-config show-config` shows the effective configuration; and `journalctl -u mvgald` works again because the canonical unit name is used.
